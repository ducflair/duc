## Overview

A **Model Element** keeps executable source or an external CAD source, generated output, and presentation state under one element ID. Its `type` remains `"model"` when its output changes between 3D, DXF, image, SVG, PDF, and table content.

The element owns its canvas position, dimensions, thumbnail, and `viewerState`. Generated bytes live in an [External File](/docs/concepts/external-files) referenced by the drawing. The output envelope identifies which viewer should display those bytes.

## Declare Python Output

A Python Model Element stores its source in `code` and uses `modelType: "python"`. The execution host provides `emit_output` as a global:

```python
from build123d import Box

width = 120
height = 80
wall_thickness = 5

wall = Box(width, wall_thickness, height)
emit_output(wall, kind="parametric")
```

Call `emit_output(...)` once per root execution. The declared `kind` selects the artifact and renderer.

### API

```python
emit_output(
    value=None,
    kind="image",
    data=None,
    path="plot.png",
    mime_type="image/png",
    filename="plot.png",
)
```

| Argument | Meaning |
| --- | --- |
| `kind` | Required: `parametric`, `ifc`, `dxf`, `image`, `svg`, `pdf`, or `table` |
| `value` | A supported geometry object, IFC file, DXF drawing, text, bytes, or table records |
| `data` | Explicit payload bytes or text, instead of converting `value` |
| `path` | A generated file inside the execution workspace; relative paths use that workspace |
| `mime_type` | MIME type override, such as `image/png` |
| `filename` | Display or export name for the artifact |

Use the input form appropriate to the kind. The file passed through `path` must exist when execution completes and must resolve inside the workspace. An empty artifact, an unsupported kind, a second declaration, or a file outside that workspace fails generation.

The API is supplied by a compatible execution host, including the `ducpy` tessellation runner. To execute model source from a Python host, use `ducpy.tessellate.runner.tessellate_model_code(...)`; a plain Python interpreter does not supply these globals.

## Output Kinds

| Kind and renderer | Artifact | Viewer |
| --- | --- | --- |
| `parametric` | JSON tessellation payload, `application/json` | Interactive CAD 3D |
| `ifc` | IFC bytes, `application/x-ifc`, plus a separate JSON preview when geometry is available | IFC 3D |
| `dxf` | DXF bytes, `application/dxf` | DXF 2D |
| `image` | Image bytes, default `image/png` | Image |
| `svg` | SVG text or bytes, `image/svg+xml` | SVG |
| `pdf` | PDF bytes, `application/pdf` | PDF with page navigation |
| `table` | JSON records or columns and rows, `application/json` | Table |

### Build123d Output Contract

Pass the completed shape to `emit_output(shape, kind="parametric")`. The runtime tessellates it into the generated JSON artifact. Source code and saved camera state remain separate from that artifact.

### IfcOpenShell Output Contract

Resolve the source by its external-file ID, create or modify the IFC model, then emit it explicitly:

```python
import ifcopenshell

model = ifcopenshell.open(resolve_external_file("building-source"))
emit_output(model, kind="ifc", filename="building.ifc")
```

`building-source` must be a runtime dependency in the Model Element's `fileIds`. IFC output preserves the IFC bytes and can produce a separate tessellated preview. The IFC file needs product geometry for a meaningful 3D view.

### DXF

```python
import ezdxf

drawing = ezdxf.new()
drawing.modelspace().add_line((0, 0), (120, 80))
emit_output(drawing, kind="dxf", filename="outline.dxf")
```

### Image, SVG, and PDF

Create the output file or bytes, then declare the artifact:

```python
import matplotlib.pyplot as plt

plt.plot([0, 1, 2], [0, 4, 3])
plt.savefig("plot.png")
emit_output(kind="image", path="plot.png", mime_type="image/png")
```

SVG can be emitted directly:

```python
svg = '<svg xmlns="http://www.w3.org/2000/svg" width="120" height="80"><rect width="120" height="80" fill="steelblue"/></svg>'
emit_output(svg, kind="svg", filename="panel.svg")
```

For a PDF generated in the execution workspace, use `emit_output(kind="pdf", path="report.pdf")`. Each example is a separate execution with one output declaration.

### Table

```python
emit_output(
    [{"part": "Beam", "length": 4.0}, {"part": "Plate", "length": 2.0}],
    kind="table",
)
```

A pandas DataFrame can be passed as `value` and is converted to records. For explicit columns and rows, pass JSON through `data`, for example `data=json.dumps({"columns": ["part", "length"], "rows": [["Beam", 4.0]]})`. Table values must be JSON-serializable; non-finite numeric values are rejected during conversion.

## Persisted Artifact and Envelope

An execution produces an `artifact` event containing a versioned envelope and the generated payload. Payload transport can use inline content, base64 bytes, or a host-managed asset URL for a large cloud result.

| Envelope field | Stored meaning |
| --- | --- |
| `version` | Output envelope version, currently `1` |
| `kind`, `renderer` | Declared output kind and viewer target |
| `mimeType`, `format`, `filename` | Payload representation and output name |
| `contentHash` | SHA-256 of the generated bytes |
| `sourceFingerprint` | SHA-256 of root source and the supplied dependency-module source |
| `inputFingerprints` | External input IDs mapped to SHA-256 content hashes |
| `runtime` | Python version and `contractVersion: 1` |
| `status` | `"fresh"` on a successfully emitted artifact |

Compatible hosts store this envelope in `customData.modelOutput` with `fileId`, `cacheKey`, `generation`, and `generatedAt`. An IFC output can also reference `previewFileId`. The referenced output and preview IDs are included in `fileIds`; their bytes are stored in external-file revisions, not in the element record. Generated output and preview files are excluded from the next execution's runtime inputs.

Generating and failed execution state is recorded in `customData.modelOutputState`, keyed by generation. Source, input revisions, and dependency identity determine whether a stored artifact is current. A file save alone does not generate an artifact or establish that it is current.

### Freshness and Thumbnails

| Visible state | Meaning |
| --- | --- |
| Fresh | A saved output matches the current source, dependency modules, and external-input revisions |
| Stale | An output exists, but its generation no longer matches the model inputs |
| Missing | The model has no saved output artifact |
| Failed | Generation for the current inputs failed; the error is available in model properties |

A host can display current persisted output on reopen without rerunning Python. Generation scheduling, local or remote execution, authorization, and thumbnail regeneration are host responsibilities.

Thumbnail completion changes derived pixels and freshness metadata. It adjusts the canvas bounds to the captured image's aspect ratio while preserving the longest dimension, the element ID, external source relationships, and saved viewer state. A result from an older source or input generation cannot replace the current model's output.

## Runtime Inputs and Modular Models

A model's source assets are also referenced through `fileIds`. Resolve them by external-file ID:

```python
source_path = resolve_external_file("linked-file-id")
```

The host resolves the active revision and mounts readable bytes into the execution workspace. In a desktop offline drawing, that revision may use a permitted native [relative or absolute locator](/docs/concepts/external-files#local-file-locators). A sandbox path is temporary and should not be stored as the source locator.

Python Model Elements can import parameters and functions from other Model Elements through `duc_model.<element-id>`. Only the root emits the final artifact; helper modules expose reusable values and functions. Dependency source and input changes invalidate the dependent root's output. See [Model Element Modularization](/docs/concepts/model-modularization) for import forms and graph rules, and [Using Fonts](/docs/guidelines/using-fonts#python-model-elements) for mounted font inputs.

## External CAD Sources

For a model opened directly from a file, use `modelType: "ifc"`, `"step"`, `"stl"`, `"dxf"`, or `"dwg"` and reference the source External File through `fileIds`.

IFC, STEP, and STL use their corresponding model adapters for a 3D preview. DXF uses a 2D CAD viewer. DWG is converted to a cached DXF representation while retaining the original DWG as the source. Derived output does not replace the source-file reference.

## Bridging 3D Depth to the 2D Canvas via `viewerState`

Physical engineering review and project documentation rely on 2D projections (plans, elevations, sections, and callouts).

The Model Element handles 3D spatial geometry by storing an explicit 3D camera projection state inside its `viewerState` attribute.

```ts
export type DucModelElement = _DucElementBase & {
  type: "model";
  modelType: string | null;
  code: string | null;
  thumbnail: Uint8Array | null;
  fileIds: ExternalFileId[];
  viewerState: Viewer3DState | null;
};
```

### The 3D Viewer State Data Structure (`viewerState`)

The `viewerState` field records spatial camera and projection parameters:

- **Camera Spatial State**: Camera position coordinates, target focus point, quaternion rotation, and zoom scale.
- **Projection Mode**: Orthographic versus perspective projection settings.
- **Orientation Presets**: Standard view direction indicators (Top, Bottom, Front, Back, Left, Right, Isometric).
- **Section Clipping**: Active 3D cross-section clipping plane definitions along X, Y, and Z axes.
- **Material & Analysis Settings**: Surface lighting parameters, metalness, roughness, and zebra line reflection analysis modes.

By storing `viewerState` directly inside the element record, `.duc` preserves an exact 3D spatial viewpoint projection on the 2D canvas, allowing runtimes to render the defined perspective while maintaining complete 3D spatial parameters in the file format.

## Stored Model State

Model Elements preserve the source and presentation state needed to reproduce their view:

- **Procedural Source**: Python model code remains executable and can be re-evaluated after its variables or linked dependencies change.
- **External Source Revisions**: Source assets remain attached through `fileIds` and retain their DUC revision metadata.
- **Generated Output**: Referenced artifact bytes, output metadata, and fingerprints allow the host to select a viewer and check freshness on reopen.
- **Interactive Presentation**: `viewerState` preserves the camera, projection, clipping, and material settings independently from the model source.
